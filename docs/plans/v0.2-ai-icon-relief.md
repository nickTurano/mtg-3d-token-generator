# v0.2 AI Icon Relief Implementation Plan

> **For Hermes:** Use test-driven-development skill while implementing this plan.

**Goal:** Add a first working AI-icon-to-printable-relief pipeline for standard-card-size token SVGs and STLs.

**Architecture:** Keep AI generation isolated behind a provider interface so the core pipeline is testable without network calls. Generate/cache prompts and raw icons, post-process icons into black/white silhouettes, embed processed icons into SVGs, and convert processed icon pixels into low-resolution raised STL relief rectangles.

**Tech Stack:** Python, Pillow, Typer, pytest. The first AI provider is a deterministic placeholder provider suitable for local tests; a real image provider can be wired in next without changing processing/STL code.

---

## Task 1: Icon artifact paths and deterministic placeholder generation

**Objective:** Create reusable icon path helpers and a deterministic local icon generator used when real image generation is unavailable.

**Files:**
- Create/modify: `src/mtg_token_generator/ai_icons.py`
- Test: `tests/test_ai_icons.py`

**Acceptance criteria:**
- `icon_paths(token, output_dir)` returns prompt/raw/processed paths.
- `generate_placeholder_icon(token, path, force=False)` writes a square PNG.
- Existing raw icon is reused unless `force=True`.

## Task 2: Process raw icons into printable silhouettes

**Objective:** Convert raw icon images to centered black/white silhouettes.

**Files:**
- Create: `src/mtg_token_generator/icon_processing.py`
- Test: `tests/test_icon_processing.py`

**Acceptance criteria:**
- Output image is mode `1` or `L` with only black/white values.
- Output dimensions are configurable and square.
- White margin is preserved around icon content.

## Task 3: Pipeline generates and embeds processed icons

**Objective:** Update pipeline to produce raw and processed icons before SVG/STL rendering.

**Files:**
- Modify: `src/mtg_token_generator/pipeline.py`
- Test: `tests/test_pipeline.py`

**Acceptance criteria:**
- `generate_from_tokens(..., generate_icons=True)` writes raw and processed PNGs.
- SVG output references processed icon path.
- Existing tests still pass.

## Task 4: STL bitmap relief generation

**Objective:** Convert black pixels in a processed icon into raised low-resolution STL relief tiles on the card base.

**Files:**
- Modify: `src/mtg_token_generator/stl_generator.py`
- Test: `tests/test_stl_generator.py`

**Acceptance criteria:**
- `render_stl(..., icon_path=processed_icon)` includes additional relief triangles.
- Relief is bounded within the card art area.
- Pixel sampling is capped to keep STL size manageable.

## Task 5: CLI controls

**Objective:** Add CLI flags for icon generation and regeneration.

**Files:**
- Modify: `src/mtg_token_generator/cli.py`
- Test: `tests/test_cli.py` if practical, otherwise verify help output.

**Acceptance criteria:**
- CLI exposes `--generate-icons/--no-generate-icons`.
- CLI exposes `--regen-icons`.
- `generate-all` can run full v0.2 pipeline.
