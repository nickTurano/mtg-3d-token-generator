# v0.4 Production Token Pipeline Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Turn the current OpenAI-backed token generator into a reliable production pipeline for previewing, printing, and eventually listing 3D printed tabletop token accessories.

**Architecture:** Keep generation stages isolated and testable: Scryfall metadata -> prompt generation -> icon provider -> icon processing -> SVG/STL rendering -> preview rendering -> Shopify/export metadata. Continue avoiding official MTG artwork, mana symbols, card frames, set symbols, logos, and copyrighted characters.

**Tech Stack:** Python, Typer, Pillow, pytest, OpenAI image API, Scryfall API.

---

## Current baseline

Already implemented:

- Scryfall token lookup with fallback from main set code to token set code, e.g. `sos` -> `tsos`.
- Normalized `Token` model and `tokens.json` output.
- Guardrailed icon prompts with subject-specific guidance for Bird and several common types.
- Provider abstraction with `placeholder` and `openai` providers.
- OpenAI `gpt-image-2` raw icon generation.
- Transparent processed icon PNGs.
- SVG rendering with color identity markers.
- STL card plaque rendering with MVP bitmap relief.
- CLI flags for icon generation, regeneration, and provider selection.

## Milestone 1: First-class preview rendering

### Task 1: Create preview renderer module

**Objective:** Generate polished PNG previews from token metadata and processed transparent icons.

**Files:**
- Create: `src/mtg_token_generator/preview_renderer.py`
- Test: `tests/test_preview_renderer.py`

**Acceptance criteria:**
- `render_preview(token, output_dir, icon_path=None)` writes `previews/<token.slug>.png`.
- Preview is 635x889 px by default.
- Processed RGBA icon is pasted using alpha, so card background shows through.
- Preview includes token name, type line, oracle text if present, power/toughness if present, and color identity markers.
- Colorless tokens show a neutral `C` marker.

**Verification:**

```bash
~/venvs/mtg-token-generator/bin/pytest tests/test_preview_renderer.py -q
```

### Task 2: Wire previews into pipeline

**Objective:** Let the core pipeline optionally generate previews alongside SVG/STL.

**Files:**

**Acceptance criteria:**
- `generate_from_tokens(..., generate_previews=True)` returns a `previews` list.
- Preview generation uses the processed icon when available.
- Existing behavior is unchanged when `generate_previews=False`.

### Task 3: Add CLI flag for previews

**Objective:** Make preview generation available from the CLI.

**Files:**

## Milestone 2: Improve common token prompt guidance

### Task 4: Add subject guidance test cases

**Objective:** Lock in recognizable prompt guidance for common token subjects.

**Files:**
- Modify: `tests/test_ai_icons.py`

**Acceptance criteria:**
- Tests cover at least: Copy, Elemental, Fractal, Inkling, Pest, Spirit, Treasure, Zombie, Goblin, Bird.
- Each test asserts concrete anatomy/object words that should appear in the prompt.

### Task 5: Expand prompt guidance table

**Objective:** Improve OpenAI generation quality by making subjects concrete and recognizable.

**Files:**
- Modify: `src/mtg_token_generator/ai_icons.py`

**Acceptance criteria:**
- `Copy`: overlapping duplicate silhouettes/cards/shapes, no text.
- `Elemental`: bold humanoid energy/stone/flame form; use color identity mood when possible.
- `Fractal`: geometric creature with repeating angular shapes, not abstract decoration only.
- `Inkling`: small black flying ink creature with wings and dripping silhouette.
- `Pest`: small insect/parasite body, legs, mandibles, simple readable outline.
- `Spirit`: wispy ghost silhouette, trailing tail, simple face holes, floating posture.
- `Treasure`: chunky treasure chest or faceted gem, no coin numbers/symbols.
